# WCS-GNCCP Molecular Graph Kernel Pipeline

This folder contains the mathematically optimized, final implementation of the **2D Topological WCS-GNCCP Pipeline** along with its academic theoretical documentation and GPU acceleration tools. 

This pipeline accurately computes similarities between molecular graphs by solving the Weighted Common Subgraph (WCS) problem using Graduated Non-Convexity and Concavity Procedure (GNCCP) and Frank-Wolfe optimization.

## 📂 Directory Structure & File Descriptions

### 1. Core Algorithm
*   **`wcs_gnccp.py`**: The beating heart of the pipeline. Contains the heavily optimized, CPU-bound implementation of the WCS-GNCCP algorithm. It features $O(n^2)$ rank-one matrix factorizations, Frobenius normalizations for scale invariance, and early termination via the Frank-Wolfe Duality Gap.

### 2. Theory & Academic Documentation
*   **`wcs_gnccp_theory.tex` / `.pdf`**: The formal IEEE-formatted academic paper proving the mathematical foundations of the pipeline. It contains full proofs for the structural gradient, early-stopping duality gaps, continuous continuous relaxation rules, and complexity analysis.
*   **`Guide_review3.tex`**: Report/Review documentation related to the project review.

### 3. Benchmarking & Evaluation
*   **`evaluate_all_local.py`**: A local CPU benchmarking script. It iterates over standard datasets (e.g., Aromatase, LBD, MMP, p53) using small samples to evaluate the SVM classification accuracy of the 2D kernel.
*   **`run_svm_benchmark.py`**: The core SVM training and evaluation harness. Takes the computed similarity kernels (with Eigenvalue Ridge Correction for PSD) and runs k-fold cross-validation.
*   **`evaluate_colab.py` & `README_Colab.md`**: Scripts and specific instructions designed to easily port and run the CPU benchmarks on a Google Colab instance.

### 4. GPU Acceleration (For Massive Datasets)
Because the Frank-Wolfe operations are cubic $O(n^3)$, evaluating $10,000 \times 10,000$ matrices locally is too slow. We built GPU-accelerated PyTorch versions for the cloud.
*   **`generate_kaggle_gpu.py`**: A generator script. When executed, it programmatically writes a flawless Jupyter Notebook containing the heavily optimized PyTorch (CUDA) version of the algorithm.
*   **`Kaggle_GPU_Benchmark.ipynb`**: The resulting GPU notebook ready to be uploaded and run on Kaggle (utilizing T4x2 or P100 GPUs).

### 5. Visualization & Demos
*   **`generate_2D_to_3D_mapping_image.py`**: Takes the bijective (1-to-1) atom map generated by Stage 1 (2D) and visualizes the geometric Kabsch alignment in 3D.
*   **`create_notebook.py`**: Utility script to generate interactive visualization notebooks.
*   **`Interactive_Mapping_Demo.ipynb`**: A visual, interactive notebook demonstrating how the algorithm maps atoms between two molecules step-by-step.
*   **`3D_Mapping_Visualization.png`**: Sample output of the 3D projection.

## 🚀 How to Implement & Run

### 1. Local CPU Testing
To test if the pipeline works and get a baseline accuracy on your local machine:
```bash
python evaluate_all_local.py
```
*This will automatically pull subsets from the `Data/` directory and print out classification accuracies.*

### 2. Massive Cloud Execution (GPU)
For the full datasets (100+ molecules requiring thousands of pair comparisons):
1. Run `python generate_kaggle_gpu.py` to ensure you have the latest PyTorch code inside the notebook.
2. Upload the `Kaggle_GPU_Benchmark.ipynb` to Kaggle or Colab.
3. Turn on the GPU accelerator in the cloud settings.
4. Run all cells. The GPU will compute the full kernel matrix in a fraction of the time.

### 3. Visualizing a Match
If you want to see *how* it matches two specific molecules visually:
1. Open `Interactive_Mapping_Demo.ipynb` in VSCode or Jupyter.
2. Run the cells to see the atom-to-atom correspondence overlay.

## 🧬 Architecture Notes
*   **Hydrogen Removal**: Hydrogens are automatically stripped out before matrix generation to cut the input size $n$ in half, achieving an 8x speedup without losing topological data.
*   **Non-PSD Kernels**: Graph-edit distances naturally violate the triangle inequality. We apply Schoenberg's exponential transform $k(G, H) = \exp(-\gamma F^* / L)$ and SVM Eigenvalue Ridge Correction ($\mu\mathbf{I}$) to safely construct valid decision boundaries.
